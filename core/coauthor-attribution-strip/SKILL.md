# coauthor-attribution-strip

Charter §2.2 hooks-over-rules. The user's standing rule
`feedback_no_claude_coauthor` says: *every commit, including those
generated by the Claude Code harness, must NOT carry a `Co-Authored-By:
Claude` (or any Anthropic) trailer.* Until v1.10.0 the rule was
enforced in two unreliable ways:

1. **Prompt-only memory** (`feedback_no_claude_coauthor` in
   `MEMORY.md`) — relies on the agent recalling the rule and
   self-suppressing. An instruction-injected or context-compacted
   agent will silently emit the trailer.
2. **PostToolUse refuse**
   (`core/governance-pack/hooks/no-coauthor-trailer.sh`) — fires
   AFTER the trailer is already in the commit message; the agent
   has to retry. Wastes tokens and surfaces a confusing error
   message on every fresh session.

This skill replaces both with a harness-native primitive: a single
`attribution.commit = ""` field in `~/.claude/settings.json` that
tells the Claude Code harness to strip generated commit-trailers at
source. The block-and-retry hook stays in place as a belt-and-
suspenders second line — but on the steady-state path the trailer
never reaches the `git commit` argv at all.

## What it does

`install.sh` adds (or canonicalizes) this jq-merge to
`$HOME/.claude/settings.json`:

```json
{
  "attribution": {
    "commit": ""
  }
}
```

The empty string is the chosen canonical value — per Claude Code
harness convention for trailer-suppression — and instructs the harness
to omit Anthropic / Claude trailers when generating commit messages.

### Why an empty string and not `false` / `null`

The Claude Code settings schema does not (as of 2026-05-04) document
a first-party `attribution` field by name in
`https://json.schemastore.org/claude-code-settings.json`. We are
adopting `attribution.commit = ""` as the convention going forward
(documented here); the surface is forward-compatible with whatever
the harness eventually ships, because:

- An empty string is the most conservative "render nothing" value
  for any future harness implementation that respects the field.
- A future harness that ignores the field is no worse off than
  today (the existing PreToolUse hook still catches the trailer).
- A `null` would risk being interpreted as "use default," which is
  exactly the trailer we are suppressing.

If/when the harness adopts a different field name, this skill's
`install.sh` will canonicalize the new field via the same matcher-
aware jq pattern (see `core/governance-pack/install.sh` §13 / §18
for the precedent — drop-then-add via jq, not duplicate-add).

## Adoption

Once `core/governance-pack/install.sh` wires this skill in (planned
v1.10.0 mini-wave integration step), operators get the field
automatically on `governance-pack/install.sh` re-run. Standalone:

```bash
bash core/coauthor-attribution-strip/install.sh             # install
bash core/coauthor-attribution-strip/install.sh --dry-run   # show plan
```

The installer:
- Backs up `~/.claude/settings.json` to a timestamped sibling before
  any write.
- Is idempotent: re-running on a settings.json that already has
  `attribution.commit = ""` is a no-op.
- Is drift-recovering: if a stale value (e.g. `attribution.commit =
  "Co-Authored-By: ..."`) is present, it is rewritten to the
  canonical empty string. (Same matcher-aware pattern as
  `governance-pack/install.sh` §13.)

## Project opt-out

Set the env var in your shell or in `<project>/.envrc`:

```bash
export COAUTHOR_ATTRIBUTION_STRIP_DISABLE=1
```

When set to `1` / `true` / `yes` (case-insensitive), `install.sh`
exits 0 without touching `settings.json`. Use this on a project where
you genuinely want the trailer — for example a public OSS repo where
Anthropic attribution is the agreed convention. The default for this
operator is OFF (= strip).

## When NOT to use

- **On a multi-tenant settings.json that's centrally managed** by a
  config-management tool. The installer writes through to
  `settings.json` directly; pair it with your CM tool's reconcile
  loop or skip.
- **In a project where Co-Authored-By: Claude is desired** (see
  opt-out above).

## Forbidden in install.sh body (TM4)

`install.sh` is shell + jq + python3-fallback only. No LLM
invocation, no sub-agent. Same TM4 contract as every other skill in
this repo.

## Composition with sibling enforcement

This skill does NOT remove
`core/governance-pack/hooks/no-coauthor-trailer.sh` — they layer:

| Layer | Site | Failure mode covered |
| --- | --- | --- |
| Harness attribution field | `~/.claude/settings.json` | Generated commit never contains the trailer |
| PreToolUse refuse | `no-coauthor-trailer.sh` | Trailer slips through (older harness, manual `git commit -m` from agent) |
| `core/git-force-push-gate` (v1.10.0 extension) | Pre-push refusal | Trailer made it into a real commit; refuse to push it |

Three layers, three different parts of the pipeline. Charter §2.2
defense-in-depth.
